# Test coverage

This page lists what the offline tests of openHUD `0.1.0` cover, by gate name and group, and what they do not. The tests never start OMSI. The managed gates are in `tests/OpenHud.Tests` (a console program, exit code 0 when every gate passes); the native ones are in `tests/native` (a C++ console program that the managed gate `draw.native-tests-pass` runs). When this page and the tests disagree, the tests win and the page is a bug.

Related pages: [validation status](validation.md), [known limitations](../reference/known-limitations.md), [the three parts](../concepts/the-three-parts.md).

## How to run them

```text
powershell -File tools\Build-Module.ps1 -OmsiLaunchRoot C:\src\OmsiLaunch
```

builds the draw layer, builds and runs the native tests, builds the managed component, assembles the module folder and runs the managed gates. The native gates `draw.native-*` fail with "the native tests are not built" if the native test program was not built first. Each gate prints `PASS` or `FAIL` with its name.

## What the tests do not cover

- Anything in a running OMSI: the real native pause menu, the real input capture, the Direct3D hooks on the game's device, the units and positions the game reports ([validation status](validation.md)).
- The appearance of text in a real font on a real machine beyond the golden checks of the software backend.
- Translation quality.
- Prose: the documentation gates check examples, tables and links (`tools\Check-Docs.ps1`), not whether a sentence is right.
